You are a senior backend engineer and database architect.

Build the complete backend for:

IVESTBOT

This backend will support the existing IvestBot React/Vite frontend.

IMPORTANT:
The backend must be production-oriented, secure, modular and ready for frontend integration.

The application has exactly 4 primary user pages:

1. Home
2. Reservation
3. Wallet

==================================================

Referral URL:

https://YOUR-DOMAIN/?ref=REFERRAL_CODE

When a new user registers with a valid referral code:

User becomes the direct referral (A member) of the referring user.

Structure:

YOU
 |
 ├── A Members
 │
 ├── B Members
 │
 └── C Members

Definition:

A = direct referrals

B = referrals generated by A members

C = referrals generated by B members

Store direct relationship in database.

DO NOT calculate the entire tree from frontend data.

==================================================
16. RESERVATION CREATION
==================================================

API:

POST /api/reservations

Flow:

1. Authenticate user
2. Start DB transaction
3. Lock user wallet row
4. Check available balance
5. Check previous reservation
6. Check nextAvailableAt
7. Reject if 24-hour period has not expired
8. Determine reservation amount
9. Create reservation
10. Create reservation ledger entry
11. Set processingAt
12. Set nextAvailableAt
13. Commit transaction

IMPORTANT:

Prevent race conditions.

Two simultaneous requests from the same user must NOT create two reservations.

Use:

database row locking
or
serializable transaction
or
unique constraint strategy

==================================================
17. 20-SECOND PROCESSING
==================================================

Reservation has a 20-second processing period.

Do not rely only on setTimeout() in the browser.

Backend should store:

processingAt
processedAt

A backend job/worker should process eligible reservations.

After 20 seconds:

1. verify reservation status
2. calculate configured profit
3. create profit ledger entry
4. settle/return the reservation amount according to the configured product rule
5. mark reservation COMPLETED
6. create notification
7. process eligible referral bonuses

IMPORTANT:

The exact financial settlement rule must be configurable.

Never create duplicate profit transactions if the worker runs twice.

Use idempotency checks.

30. MONEY HANDLING
==================================================

NEVER use JavaScript floating-point arithmetic for financial values.

Use PostgreSQL DECIMAL/NUMERIC.

Use a consistent precision.

Example:

DECIMAL(20,8)

All money calculations must be done using decimal-safe arithmetic.

Round only according to a clearly defined business rule.
